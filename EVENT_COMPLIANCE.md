## Model and data contract

- `heart_disease_uci.csv` has 920 cross-sectional rows and an existing `num` label; `static_model.load_uci_records()` maps it to `num > 0`. That label means prevalent disease in the source dataset, not an incident/future adverse event. `static_model.score_holdout_record()` scores only a held-out row using the 13 feature columns.
- The combined simulation pipeline uses `MODEL_FEATURE_COLUMNS`: 13 UCI context features plus mean, slope, and latest-value summaries of eight generated wearable measurements. It predicts whether a generated future window meets a generated HR/RMSSD/systolic-pressure rule within 30 minutes. The simulator's grouped split and tests establish software behavior and agreement with that rule, not clinical prediction or validation.
- The hand-authored EHR-like profiles and their fused snapshots are separate from the UCI-context profiles used by the trained combined model. `fuse_patient_data()` does not feed those patient snapshots into `predict_simulated_anomaly()`.
- Existing `artifacts/simulated_forecast/simulated_forecast_model.joblib` is `simulated-cardiovascular-anomaly-logistic-v1` and does not contain the v2 holdout profiles the current dashboard expects. The matching saved evaluation is historical simulator-rule evaluation, not evidence of a real adverse-event forecast. Do not present it as clinical performance.
- `artifacts/static_model/uci_heart_logistic.joblib` loaded successfully with its fitted preprocessing/classifier pipeline. A genuine inference on held-out UCI record 2 returned the prevalent-disease class; this is not a future-event result.

## Safe checks performed

- Separate imports passed for `numpy`, `numpy.random.mtrand`, `pandas`, `sklearn`, `scipy`, `joblib`, and `streamlit` using the short-path project junction.
- Eight `test_simulated_forecast.py` tests and three `test_static_model.py` tests passed. The forecast tests train in memory and write persistence checks only to temporary test directories.
- The dashboard page loaded in a browser; its health endpoint returned HTTP 200. The Digital Twin forecast displayed a v2 model, a 30-minute horizon, and explicit simulation-only provenance. The UCI workspace displayed its held-out record output and identifies its target as `num > 0`.
- Original model artifacts were not modified by these audit checks. No security settings were changed.
- **Current run command (from project root):** `.\.venv\Scripts\python.exe -m streamlit run atria_twin/app.py`. Do not run it against the original artifact directory until its v1-to-v2 retraining/write behavior is made non-overwriting.

## Three highest-priority gaps

1. **No genuine future adverse-event target or patient-linked model input.** The 30-minute output is a synthetic threshold rule, and the trained model's UCI context is not the hand-authored EHR stream. Required work/data: approved linked longitudinal input and outcome dataset; `atria_twin/simulated_forecast.py`; `atria_twin/patient_records.py`; `atria_twin/forecast_dashboard.py`; `atria_twin/app.py`. This is not a credible code-only or three-hour fix without the data.
2. **The public repository does not contain the audited Atria Twin snapshot.** The discovered public repo is the legacy single-visit classifier, while this local project has no Git metadata and Git is unavailable. Required work: publish the current `atria_twin/`, `tests/`, `docs/`, `deliverables/`, `README.md`, `LICENSE`, and `requirements.txt` after access and redistribution-rights checks. Do not misrepresent the current public repository as containing this project.
3. **The required 20-minute video is missing.** Required work: record/export the walkthrough described in `docs/SUMMIT_DEMO_SCRIPT.md`, then publish the video or an accessible submission link. The existing script and slide decks do not satisfy the video requirement.
